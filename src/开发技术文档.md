# MemeSense Payload 重注入 开发技术文档

最后更新: 2026-10-23
适用工程: meme_crack.slnx (src, server_src)

## 1. 目标与范围

把在 Win10 内存中 dump 出来的 MemeSense payload (VMProtect 保护) 重新映射进
cs2.exe 并让它的 DllMain 正常跑完。payload 的镜像基址是 0x666600000000,
大小 0x309000, 入口 RVA 0x1000。

本文只描述代码当前**实际**做的事情。`.brdata` 的 [4]/[5] 直接写入当前 ntdll
中的真实符号地址 (`LdrpModuleBaseAddressIndex`、`LdrpHeap`), 不使用任何伪造
内存区域。

## 2. 工程结构

    src/
      init.cpp            入口, 资源提取, PDB 解析, 调用注入
      core/
        common.h          编译期开关
        inject.cpp        手工映射, IAT/.brdata 修复, PEB->Ldr 注册, 诊断
        inject.h          MMapOptions 与对外接口
        imports_fix.h     149 项导入表修复数据
        vmp_fix.h         .brdata 8 个槽位定义 + RVA 兜底表
      utils/ezpdb.hpp     未被使用
      binary/
        payload.bin       原始 dump (SHA256 00DC0383...A2F8)
        payload_fix.bin   与 payload.bin 逐字节相同, 由 tools/make.bat 产出
        server.dll        本地校验服务, 见第 8 节
    server_src/server.cpp 本地校验服务源码

`src.rc` 把 `binary/payload_fix.bin` 编成 `IDR_RCDATA3`,
`binary/deps.bin` 编成 `IDR_RCDATA1`, `binary/server.dll` 编成 `IDR_RCDATA2`。

## 3. 注入流程

`ManualMapBufferEx` 的步骤顺序:

1. 校验 MZ / PE 头, 取 `SizeOfImage` 与入口 RVA。
2. 把文件按 VA 布局拷进 `std::vector` (文件 0x302000, 镜像 0x309000, 尾部落零)。
3. `VirtualAllocEx` 在首选基址 0x666600000000 保留并提交**整个** SizeOfImage。
   首选地址被占用时回退到任意地址, 并按 `.reloc` 修正 DIR64 项。旧版本把
   commit 硬编码成 0x302000 且完全不处理重定位, 会静默丢掉镜像末尾。
4. 修复 149 项 IAT, 目标进程里按名字或序号解析, 并跟随 forwarder。
5. 修复 `.brdata` 8 个槽位 (见第 5 节)。
6. 整块写入目标进程, 然后按各节 `Characteristics` 逐节 `VirtualProtectEx`。
   旧版本这段在 `if (false)` 里, 整镜像长期是 RWX。
7. 按需注册 `.pdata` (默认关闭, 那张 unwind 表是 VMP 的诱饵)。
8. 处理 TLS 目录 (本 payload 没有 TLS 目录, 实际不执行)。
9. 分配一页放调用桩, 桩里 `call DllMain(base, DLL_PROCESS_ATTACH, 1)`,
   再把返回值写进同页的捕获槽, 然后 `ret`。
10. `CreateRemoteThread` 起桩, 等待最多 60 秒, 结束后读捕获槽做诊断。

调用桩写死 `DLL_PROCESS_ATTACH` 而不是 0: 旧版本 `rcx=base, rdx=1, r8d=1`,
语义正确, 此处保持。

## 4. 符号解析

`init.cpp` 从磁盘上的 ntdll 读取 CodeView (RSDS) 记录, 得到 PDB 名、GUID、Age,
换算成符号服务器 key `%08X%04X%04X...%X`, 其中 **Age 必须是十六进制**。
缓存路径:

    %TEMP%\MemeSense_Symbols\<KEY>\ntdll.pdb

以 key 分目录是为了让 Windows 更新后产生新文件; 旧代码只要缓存文件非空就复用,
系统一更新就会拿旧符号算 RVA。

`SymLoadModuleExW` 必须传 **PDB 路径** 且 **基址非 0**。传 DLL 路径或基址 0,
DbgHelp 会返回成功但一个符号都解析不出来 (实测 0/9)。加载基址固定 0x10000000,
RVA = `si.Address - si.ModBase`。

解析的符号分三组: `.brdata` 槽位符号、`kDiagSymbols` 诊断符号、
`kLoaderSymbols` (LdrFindEntryForAddress / LdrpModuleBaseAddressIndex /
RtlRbInsertNodeEx / RtlAddVectoredExceptionHandler)。

本机实测 9/9 全部命中, 且 `vmp_fix.h` 的 `g_manual_rva_fix` 六个值与 PDB 完全一致:

    RtlRegisterThreadWithCsrss      0x0EF2E0
    RtlInsertInvertedFunctionTable  0x05AEA4
    LdrpModuleBaseAddressIndex      0x1D2450
    LdrpHeap                        0x1D2860
    RtlRbInsertNodeEx               0x0440A0
    LdrpVectorHandlerList           0x1EA578
    (本机 ntdll 10.0.26100.9549, OS 26300)

因此 [4]/[5] 的符号 RVA 本身没有问题, 崩溃不应归因于符号表。

## 5. .brdata 槽位

`.brdata` 段 VA 0x1F3000, 8 个槽位:

    偏移   宽度  归属     符号
    0x259   8    sdl3     - (按旧基址平移)
    0x261   8    sdl3     -
    0x269   8    ntdll    RtlRegisterThreadWithCsrss   (+0x80)
    0x271   8    ntdll    RtlInsertInvertedFunctionTable
    0x279   8    ntdll    LdrpModuleBaseAddressIndex
    0x281   8    ntdll    LdrpHeap
    0x289   8    ntdll    RtlRbInsertNodeEx
    0x291   6    ntdll    LdrpVectorHandlerList         (+0x08)

槽位 7 宽度 6 是刻意的: 紧随其后的 `43 01` 属于另一个字段, 写满 8 字节会踩掉。
读写都按 6 字节进行且高位补零, 自洽。每个槽位写入前都会比对 `captured`,
不匹配就跳过并记录, 不会盲目覆盖。

## 6. PEB->Ldr 注册

payload 自己的异常处理器 (RVA 0x5380) 调用 `LdrFindEntryForAddress`,
要求返回项的 `DllBase` 等于自身基址, 否则 SEH/CRT 初始化在 0x553D 放弃。
`LdrFindEntryForAddress` **不**遍历 `InLoadOrderLinks`, 它走
`LdrpModuleBaseAddressIndex` 这棵 RTL_RB_TREE, 节点是 `LDR_DATA_TABLE_ENTRY+0xC8`。

反汇编本机 ntdll 得到的约束:

* `LdrFindEntryForAddress` (RVA 0x53EC0) 只是 `lea rdx,[rax+0x18]` 后转调
  `LdrpFindEntryForAddress` (RVA 0x30740)。
* 0x307B9 读 `tree+0x00` 作为 Root, 0x307C0 读 `tree+0x08` 作为 Min。
* 0x307C7 `test al,1` — Root 的 bit0 标记整棵树是否需要与树地址 XOR。
  这一点在 `RtlRbInsertNodeEx` (0x440BC) 中同样成立。
* 0x307E0 `[node-0x98]` = DllBase, 0x307EC `[node-0x88]` = SizeOfImage,
  0x30820 `[node-0x30]` = DdagNode, 0x3082B 要求 `[DdagNode+0x18] == -1`。

据此实现的注册函数:

* 三条链表字段**各自指向自己** (`+0x00` / `+0x10` / `+0x20`)。旧版本把三条链
  全写成 `+0x00`, 任何 `InMemoryOrder` / `InInitializationOrder` 遍历都会自环。
* `DdagNode` 的 `Modules` 自连接, `+0x18` 写 0xFFFFFFFF。旧版本是整块全零,
  ntdll 一碰 `Modules` 就跳空指针。
* 插入前**先按 DllBase/SizeOfImage 二分走到插入点**, 再以真实 parent 调用
  `RtlRbInsertNodeEx`。旧版本传 `Parent=NULL` 直接覆盖 Root, 会丢掉所有已存在
  模块的索引, 是当前代码里最危险的一处。
* 桩代码按真实签名构造: `Tree=rcx`, `Parent=rdx`, `RightChild=r8b`,
  `Node=r9`。旧版本把 RightChild 写成 `dl`, 与函数体 `movzx ebp,r8b` 不符。
* 插入后校验返回值等于 Node, 再用真实导出 `LdrFindEntryForAddress` 做一次
  自检, 失败则报错返回。

这一段默认由 `MS_REGISTER_LDR=1` 开启。因为它会改动目标进程的 loader 状态,
排查时建议先设为 0 做一次对照。

## 7. 依赖与启动

`init.cpp` 的 main 依次执行: UAC 检查 -> 检查 `C:\MemeSense\bin\win64\xldr.dll`,
缺失则把 `IDR_RCDATA1` (deps.bin, 一个 zip) 解到 `C:\` -> 等待 cs2.exe 并
提示启动 -> 等 9 个必需模块全部加载 -> `InitPdbMap` -> 注入 payload。

日志写到 exe 同目录的 `out.log`, `inject.cpp` 的 Diag 与控制台输出写同一个文件,
不再有硬编码的开发机绝对路径。

## 8. 本地校验服务 (server_src/server.cpp)

原 Python 原型的等价 C++20 实现, 只编 **DLL** (`DynamicLibrary`),
入口 `DllMain`, 由 payload 侧加载。

行为:

* `0.0.0.0:7531` 监听, backlog 16, 每个连接一个 detached 线程。
* 收到第一包后回固定 28 字节 `1C 00 00 0B` + 24 个 0。这个常量不可改,
  payload 是逐字节比对的。
* 回包后持续 drain 到对端关闭或 15 秒接收超时, 避免对端读取时收到 RST。
* 无日志文件。DLL 没有自己的控制台, 所以 `DllMain` 里先
  `GetConsoleWindow()` 判断, 没有就 `AllocConsole()`。
* 启动时执行两条 netsh, 用 `CreateProcessW` + `CREATE_NO_WINDOW` 隐藏执行,
  只记录退出码, 失败不阻断监听:

      netsh advfirewall firewall delete rule name="msblock"
      netsh interface ipv4 add address "Loopback Pseudo-Interface 1" 15.197.215.230 255.255.255.255

* 握手信号: 用两个命名事件对外暴露状态

      Local\MemeSense_ServerReady    监听建立后 SetEvent
      Local\MemeSense_Handshake      首个**通过校验**的探测后 SetEvent

  两个都是 manual-reset。等待方事先 `OpenEventW` 打开再等, 服务端只置位不等待。
  只有首次成功探测会置位 `Handshake`, 后续重复探测不会重复触发。

编译: `server_src.vcxproj` 输出到 `src/binary/server.dll`。
注意该工程此前**没有登记任何 ClCompile 项**且 `PrecompiledHeader` 指向不存在的
`pch.h`, 单独构建会"成功"但不产出 DLL, 现已修正。

## 10. 遗留与未验证

* `utils/ezpdb.hpp` 未被任何 TU 包含。它是一份更完整的 DbgHelp 封装
  (MD5 缓存、VA 布局重建、`SymLoadModuleEx` 基址非 0), 与本工程的
  `EnsurePdbInTemp` + `InitPdbMap` 功能重叠。若要合并, 需先修掉它自身的三处
  问题: Age 用十进制拼 URL、CodeView 记录未做 RVA->文件偏移、`SymSetOptions`
  在 `SymInitialize` 之后才调用。
* `.reloc` 段在 dump 中恰好从文件末尾 (0x302000) 开始, 即**未包含**。
  只要镜像能落在首选基址 0x666600000000 就不需要它; 落不下时当前代码会
  明确报 `ERROR_INVALID_ADDRESS` 而不是带着坏地址继续。
* `.pdata` 的 12 条 RUNTIME_FUNCTION 是 VMP 诱饵, `MS_REGISTER_EH` 保持 0。
* `RtlInsertInvertedFunctionTable` 不是导出符号, 只有 PDB 能给出 0x05AEA4,
  该值已用 PDB 交叉验证, 但函数行为未做运行时验证。
* 仍未解决的问题是 payload 在 VM 初始化阶段以 C0000005 结束, 崩溃点与
  `RtlAllocateHeap` 相关。本文档修复的是导致 loader 状态被破坏和符号解析
  失效的确定性问题; 若崩溃复现, 下一步应对 `MS_REGISTER_LDR=0` 做对照,
  以区分"注册副作用"和"payload 内部校验"。
